A neural network from scratch in NumPy

I wrote this in sixth form because I wanted to know whether I could actually derive backpropagation myself rather than just calling a library that already does it. The rule I set was that NumPy was allowed to do matrix multiplication and that was all, so no autograd, no layers, no optimiser, and every gradient in the file is one I had worked out on paper before I typed it in.

It is the same network you can draw on from the front page, running the weights I trained back then rather than a retrained copy.

The shape of it

There are 784 inputs, one per pixel of a 28 by 28 image, then a hidden layer of 20, a second hidden layer of 10, and 10 outputs for the digits. ReLU sits between the hidden layers, softmax is at the end and the loss is cross entropy.

The weights start off random but scaled by the square root of two over however many inputs that layer has, which I did not think would matter very much when I first read about it. It does matter though. If you initialise a ReLU network from a plain normal distribution the activations shrink at every layer, and by the time the gradients have travelled back to the first set of weights there is so little signal left that they barely move at all.

The one bit of maths worth knowing

Most of the backward pass is the chain rule applied patiently and it is fairly tedious to derive, but there is one result at the end that makes it worth doing. The gradient of the loss with respect to the final pre-activation comes out as:

dC_dz3 = a3 - y

which is just the prediction minus the truth. Softmax on its own has a fairly unpleasant derivative and so does cross entropy, and when you compose the two nearly all of that cancels out. If I had read it in a textbook I would have believed it and moved on, whereas having gone through the algebra I know why the two are almost always used together.

After that it is mechanical. You push the error backwards through each weight matrix with a transpose, multiply by the derivative of ReLU (which is only a mask of wherever the input was positive) and repeat. Every gradient is averaged over the batch, and my batch is the entire training set, so this is ordinary full batch gradient descent with a learning rate of 0.1.

Being careful with the data

The images come in as a CSV of 42,000 rows. I shuffle it, keep the first thousand back as a test set, train on everything else, and divide the pixels by 255 so the inputs sit between 0 and 1.

Keeping that thousand back is the part that stops you fooling yourself, since a network can classify an image it has already been trained on without having learned anything general at all, so measuring on the training set tells you almost nothing.

Changing one thing at a time

Once it was training properly the more interesting part was arguing with it. There is an experiments folder where each file changes exactly one thing and leaves the rest alone: sigmoid instead of ReLU, a 16 and 16 hidden pair instead of 20 and 10, one hidden layer, three hidden layers, no biases at all, mini batches instead of full batch, and a training set I deliberately made too small.

That last one is the one worth running yourself. Starve it of examples and the training accuracy carries on climbing quite happily whilst the test accuracy flattens off, and watching those two lines come apart taught me more about overfitting than anything I had read about it.

Getting it into a browser

The demo on this site runs the same network. I exported the six arrays as base64 float32 into a JSON file and rewrote the forward pass in JavaScript, which is only three matrix multiplies, so that part was not really the problem.

The problem is that whatever you draw on a canvas is not what MNIST actually looks like. Those digits were scaled to fit inside a 20 pixel box and then positioned by their centre of mass within a 28 pixel frame, so a stroke drawn anywhere on a blank canvas comes from a completely different distribution and the network will get it wrong whilst behaving exactly as it was trained to. So before anything is fed in, the canvas is cropped down to the ink, scaled so the longest side is 20 pixels, and shifted so the centre of mass ends up in the middle.

The weights I saved get 95.8% across all 42,000 labelled images and 96.8% on the thousand it never trained on. It is a small network trained in about the simplest way there is, and I would rather put the number I can reproduce on here than the best one I happened to see while I was tuning it.

Was it worth not using a library

For learning it definitely was. I use PyTorch now and it is better in every way you could measure, but loss.backward() means something different to me than it would have done if I had started there, because I have written the loop that it stands in for.
