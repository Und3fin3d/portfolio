Porting a chess engine from Python to the browser

For my second-year AI coursework I wrote an engine for Chess Fragments, a 5×5 variant whose corner piece, the Right, moves as a rook and a knight combined. The engine that plays on the front page of this site is that coursework, ported line by line from Python to JavaScript.

Most of it translated mechanically. The board has 25 squares, so a bitboard fits comfortably inside the 32 bits that JavaScript's bitwise operators actually use; a plain number does the job with no BigInt in sight. Move generation, make and unmake, the piece values, the piece-square tables and the whole search stack came across unchanged: negamax with alpha-beta, a Zobrist-hashed transposition table, killer and history move ordering, null-move pruning, late move reductions, check extensions and a delta-pruned quiescence search.

What didn't survive

Magic bitboards. The Python engine uses the multiply-and-shift trick for sliding attacks, but it needs fast 64-bit integer multiplication, which JavaScript numbers can't do and BigInt does too slowly to sit inside a search loop. The browser version falls back to classic ray lookups instead. On a 25-square board the difference is negligible; the tables are tiny either way.

Keeping it honest

The point of the port was faithfulness. It would have been much easier to drop in a generic small-board engine, but then the demo would be a lie. Piece values and square tables are copied verbatim from the Python source, the Right generates the same rook-plus-knight moves, pawns keep their double-push and en passant, and the move ordering follows the same hash-move, capture, killer, history sequence.

With 350 ms per move the JavaScript version reaches depth 10 to 11, searching roughly 400,000 nodes. The source is unminified: view source, and js/chess.js is all there.
